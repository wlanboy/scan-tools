Kompromittierte PyPI-Releases

Diese Releases von litellm enthielten Schadcode (Credential-Stealer, Backdoor), der beim Start jedes Python-Interpreters läuft, auch ohne import litellm:

Wer eine davon installiert hatte, sollte das System als kompromittiert behandeln und alle erreichbaren Zugangsdaten (Cloud, SSH, CI, API-Keys) rotieren. Prüfen: pip show litellm und nach *.pth-Dateien in site-packages suchen.

Die Daten konnten nicht automatisch geladen werden (z. B. weil die Seite per file:// geöffnet wurde).

Fix: erste gepatchte Version je Backport-Linie · keiner = Quelle nennt nur die letzte betroffene Version · Release meiden = Schadcode im PyPI-Paket · Quelle: OSV (GitHub Security Advisories, PyPA, OpenSSF Malicious Packages)
